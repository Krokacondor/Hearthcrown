# M0 Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An empty but correctly shaped Hearthcrown project. It runs in the browser and shows the empty diorama: a grassy tile-grid ground on a wooden base, lit by a sun, with a camera that turns in 45° steps and zooms. The view fits desktop and landscape-phone screens. The project has a tested seeded RNG and a minimal sim state, exposes the dev-only `window.__hearthcrown` hook, and has `PRODUCT.md` and `DESIGN.md` from Impeccable.

**Architecture:** `src/sim/` holds pure logic (RNG, world, game commands) with no DOM. `src/render/` builds the Three.js scene from palette constants that mirror `DESIGN.md`. Camera math and key mapping are pure functions, so they are unit-tested without WebGL. `src/main.ts` wires the page, and `src/debug.ts` installs the debug hook only in dev builds through a dynamic import, so it is stripped from production.

**Tech Stack:** TypeScript (strict), Vite, Vitest, Three.js (exact pinned version), Node 24 / npm 9. No game engine, no UI framework.

**Spec:** `PLAN.md` (sections 2, 2.2, 5.1, 6 row M0, 7) and `CLAUDE.md` (code rules, browser checks, Impeccable).

## Global Constraints

- TypeScript `strict: true`. Vite for dev and build. Vitest for tests. Three.js renders the world (PLAN.md 2.2); `src/sim/` never imports it.
- `src/sim/` never imports `render/` or `ui/`, never touches the DOM, never calls `Math.random()`.
- `render/` and `ui/` read sim state and call sim commands. They never change state directly.
- Tunable numbers and content go in `src/data/*.json`.
- Targets desktop browsers **and phones in landscape**. The keyboard alone must be able to play. Every focusable element has a visible focus state (PLAN.md 5.1).
- Debug hook `window.__hearthcrown` exists **in dev builds only**, with `getState()` and `cmd(name, args)`.
- Names, art and text are original.
- Work on branch `m0-scaffold`. Small commits, each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Do not push without asking.

## Review Focus

1. **Seed edge cases** (0, negative, huge, fractional, NaN): the RNG stays deterministic and never yields NaN. Invalid seeds throw. Tests in Task 1.
2. **`getState()` must be read-only**: mutating the returned object must not change the game. Test in Task 3.
3. **Unknown or malformed `cmd()` calls** (bad name, missing/invalid args) return `{ ok: false, error }` and never throw or change state. Tests in Task 3.
4. **Production build leaks the debug hook**: `npm run build` output must not contain `__hearthcrown`. Verification step in Task 5.
5. **Resize, rotation, high-DPI screens and no WebGL**: the view never gets a 0 or NaN size, the pixel ratio is clamped to 1–2 (phones with dpr 3 stay fast), it re-renders on resize, and a browser without WebGL shows a short friendly message instead of a blank page or a thrown error. `viewSize` tests in Task 5, phone-landscape screenshot in Task 6.

- [ ] **Step 4: Implement `src/sim/rng.ts`**

  Seed normalization: reject non-finite with `RangeError`, then `Math.trunc(seed) >>> 0`. Algorithm is mulberry32 (one uint32 of state):
  ```ts
  let t = (state = (state + 0x6d2b79f5) >>> 0);
  t = Math.imul(t ^ (t >>> 15), t | 1);
  t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
  return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  ```
  `int(min, max)` = `min + Math.floor(next() * (max - min + 1))`.
